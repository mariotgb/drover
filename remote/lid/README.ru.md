# lid-awake

Root LaunchDaemon: на AC — `pmset -a disablesleep 1`, на батарее или при
неизвестном источнике — `0`. Перед включением `1` питание перечитывается;
после записи проверяется ещё раз. Сброс в `0` не ждёт пауз повторных попыток.
События `pmset -g pslog` дополняются опросом каждые 15 с.

При старте на батарее и переходе AC→Battery с закрытой крышкой демон после
сброса запрета сна вызывает `pmset sleepnow`. При ошибке повторяет проверки
и попытки через 30, 60, 120 и 120 с — максимум пять проверок за один вход в
Battery. Неизвестное питание/крышка тоже расходует проверку, но не вызывает
`sleepnow`. Перед каждой попыткой питание и крышка читаются заново. AC или
открытая крышка отменяют повторы; успешный запрос сна не повторяется после
пробуждения. Состояние только в памяти: перезапуск на Battery запускает новый
цикл проверок.

Второй LaunchDaemon `dev.drover.lid-awake-guard` запускается при загрузке и
через `StartInterval 60`. Без состояния: если питание Battery и
`SleepDisabled`/`disablesleep` равно `1`, повторно проверяет питание, ставит
`0` и пишет в лог. Он не вызывает `sleepnow`, не проверяет heartbeat и не
сбрасывает флаг на AC.

Короткие вызовы `pmset` и `ioreg`, включая cleanup и установку/удаление,
ограничены 10 с помощником `lid-awake-timeout.sh`: процесс запускается в фоне,
по истечении срока завершается SIGKILL. Долгоживущий `pmset -g pslog` — поток
событий; при остановке демона он завершается отдельно. Ошибка записи в
`/Library/Logs/lid-awake.log` не мешает управлению питанием. Plist не требует
от launchd открывать этот лог для запуска службы.

## Установка и удаление

Выполняете сами:
```sh
cd /путь/к/drover/remote/lid
sudo ./install.sh
pmset -g | grep -i sleep
launchctl print system/dev.drover.lid-awake
launchctl print system/dev.drover.lid-awake-guard
tail -n 20 /Library/Logs/lid-awake.log
sudo ./uninstall.sh
```

Установщик явно создаёт `/usr/local/libexec` как root:wheel, 0755; копирует
`lid-awake.sh` и `lid-awake-timeout.sh` как root:wheel, 0755, оба plist в
`/Library/LaunchDaemons` как root:wheel, 0644. Проверяет отсутствие symlink
во всех компонентах путей скриптов, plist и лога; отклоняет небезопасные права
и ACL существующих родительских каталогов. Guard загружается первым.
Повторная установка сначала останавливает обе службы; при неполной установке
пытается остановить их и вернуть `disablesleep=0`.

Удаление отключает загрузку и останавливает оба демона. Только статус 113
(`Could not find specified service`) от `launchctl print` означает отсутствие
службы; остальные ошибки прерывают удаление файлов. После остановки удаляет
скрипты и оба plist, затем ставит `disablesleep=0`. Лог сохраняет. При ошибке
тоже пытается сбросить флаг, но если службу остановить не удалось, она может
снова включить запрет сна: устраните ошибку и повторите удаление.

## DRY_RUN

Без sudo и изменения настроек:
```sh
DRY_RUN=1 ./install.sh
DRY_RUN=1 ./uninstall.sh
DRY_RUN=1 LID_AWAKE_FAKE_PS=AC ./lid-awake.sh
DRY_RUN=1 LID_AWAKE_FAKE_PS=Battery LID_AWAKE_FAKE_LID=closed ./lid-awake.sh
DRY_RUN=1 LID_AWAKE_FAKE_PS=Battery LID_AWAKE_FAKE_DISABLESLEEP=1 ./lid-awake.sh --guard
```

Основной цикл остановите Ctrl+C. Для переключений задайте
`LID_AWAKE_FAKE_PS_FILE=/tmp/lid-ps` вместо `LID_AWAKE_FAKE_PS` и меняйте
строку файла: `AC` / `Battery` / `Unknown`. Крышку можно менять через
`LID_AWAKE_FAKE_LID_FILE=/tmp/lid-state`: `closed` / `open` / `Unknown`.
Обновляйте файлы атомарной заменой, чтобы случайная пустая строка не стала
Unknown. Только в DRY_RUN доступны `LID_AWAKE_POLL_SECONDS=1`,
`LID_AWAKE_RETRY_DELAYS='1 1 1 1'` и `LID_AWAKE_FAKE_SLEEP_FAILURES=2`
(первые два `sleepnow` завершатся ошибкой, третий — успешно). Лог идёт в stdout.

## Задержки и аварийный сброс

Обычно реакция приходит по событию; запасной опрос добавляет до примерно
15 с ожидания, а чтение питания, крышки и команды могут добавить время
(до 10 с на каждый вызов). Guard проверяет примерно раз в минуту плюс время
команд; `StartInterval` не гарантирует точного срока и пропускается во сне
или если предыдущий запуск ещё работает. Эти значения не гарантируют
максимальное время до реального сна.

При SIGTERM/SIGINT/HUP/обычном выходе основной демон пытается вернуть `0`.
SIGKILL не запускает cleanup; guard страхует оставшийся `1` только на батарее
и только если сам успешно запускается и `pmset` работает.

Аварийный ручной сброс:
```sh
sudo pmset -a disablesleep 0
```
Если основной демон продолжает работать на AC, он может снова включить `1`
при следующем переходе питания. Для постоянной отмены используйте удаление.

**Вентиляция:** только твёрдая открытая поверхность. Перед рюкзаком отключите
зарядку и убедитесь, что Mac действительно уснул. Сброс `disablesleep=0` сам
по себе не подтверждает сон; guard принудительно не усыпляет ноутбук.
На своей модели Mac и версии macOS вручную проверьте крышку без монитора и
отключение зарядки при закрытой крышке: `disablesleep` может отсутствовать в справке вашей
системы, а [штатный режим Apple](https://support.apple.com/en-us/102501)
описан для внешнего дисплея. FileVault не меняется; демоны работают после
разблокировки диска.
