# Удалённый доступ к Drover

[English](remote-access.md) · **Русский** · [Назад в README](../README.ru.md)

Начиная с **Drover 0.5.0**, Настройки → **Удалённый доступ** позволяют открыть агентов, чаты, задачи и терминалы в браузере. Этот гайд поможет настроить HTTPS через свой VPS, привязать iPhone с помощью passkey и оставить Mac доступным. Собирать приложение из исходников не нужно.

## Как это устроено

```text
Safari / веб-приложение с экрана «Домой»
        │ HTTPS, порт 443
        ▼
VPS: Caddy (сертификат TLS + обратный прокси)
        │ HTTP к 127.0.0.1:8780 на VPS
        ▼
Обратный SSH-туннель (соединение с VPS устанавливает сам Mac)
        │ зашифрованное соединение, обычно порт 22
        ▼
Mac: Drover на 127.0.0.1:7780 → herdr → ваши агенты
```

VPS служит мостом: Drover и агенты продолжают работать на Mac. Пробрасывать порты на домашнем роутере не нужно. Туннель переподключается через macOS LaunchAgent. Drover должен оставаться запущенным, а Mac — бодрствовать и иметь доступ к сети.

| Порт | Где | Для чего |
| --- | --- | --- |
| 22/TCP или ваш SSH-порт | VPS, публичный | Администрирование и подключение туннелей |
| 80/TCP, 443/TCP | VPS, публичные | Выпуск сертификата, перенаправление и HTTPS-сайт |
| 8780 | VPS, только loopback | Вход в туннель для Caddy |
| 7780 | Mac, только loopback | Веб-сервер Drover |
| 2222 / 2223 / 2224 | VPS, только loopback | Необязательный SSH к Mac / Windows / Linux |

## Что понадобится

- Mac на Apple Silicon с macOS 13.0 или новее, Drover 0.5.0 или новее, установленными herdr и агентами, которые уже работают локально.
- VPS с публичным IPv4, **Debian 12+ или Ubuntu 22.04+**, systemd, SSH и доступом root/sudo. Проще использовать новый VPS: веб-скрипт заменяет `/etc/caddy/Caddyfile`, сохраняя копию.
- Доступ к консоли VPS у провайдера на случай восстановления SSH.
- iPhone с Safari и поддержкой passkey; для уведомлений веб-приложения — **iOS 16.4+**.
- Терминал на Mac. Команды с пометкой **VPS** выполняются внутри SSH-сессии на сервере, **Mac** — локально.

Покупать домен **не обязательно**. [sslip.io](https://sslip.io/) разрешает имя с IP внутри в этот IP. Для адреса `A.B.C.D` используйте `https://A-B-C-D.sslip.io`. `203.0.113.5` / `203-0-113-5.sslip.io` — примеры для документации, а не рабочие адреса. Подставляйте свои значения.

## 1. Скачайте скрипты и создайте ключи Mac

На GitHub скачайте ветку **remote-web** через **Code → Download ZIP**, распакуйте архив и сохраните папку `remote/` в постоянном месте, например `~/drover-remote`. Скрипты доступны в [репозитории](https://github.com/mariotgb/drover/tree/remote-web/remote). В скачанном приложении Drover этих скриптов нет. Git, Node.js и Xcode не нужны.

**Mac**, в папке с `install.sh` и `bridge/`:

```bash
cd ~/drover-remote
export VPS_HOST='YOUR_PUBLIC_IPV4'
export VPS_PORT=22
export VPS_ADMIN=root
bash ./install.sh keys
```

Вместо `YOUR_PUBLIC_IPV4` укажите публичный IP VPS; при необходимости измените SSH-порт и административного пользователя. Эти переменные действуют в текущем окне Терминала; в новом задайте их снова. Команда `keys` создаёт отдельные ключи в `~/.ssh/`, не перезаписывая существующие. Для самого сайта нужен только `mac_bridge_ed25519`. Копируйте только **публичные** ключи (`.pub`). Не загружайте приватные ключи на GitHub и не отправляйте их в чат.

Подключитесь к VPS. Перед принятием SSH-ключа сервера сверьте отпечаток с консолью провайдера:

```bash
ssh -p "$VPS_PORT" "$VPS_ADMIN@$VPS_HOST"
```

В отдельном Терминале на **Mac** с теми же переменными скопируйте скрипты и публичный ключ туннеля:

```bash
scp -P "$VPS_PORT" -r ~/drover-remote "$VPS_ADMIN@$VPS_HOST:~/drover-remote"
scp -P "$VPS_PORT" ~/.ssh/mac_bridge_ed25519.pub "$VPS_ADMIN@$VPS_HOST:~/mac_bridge_ed25519.pub"
```

Если на VPS уже есть `~/drover-remote`, обновите его файлы осознанно, чтобы не получить ещё одну вложенную папку.

## 2. Настройте VPS

Не закрывайте первую административную SSH-сессию до завершения настройки. Если вы вошли как root в минимальную систему без `sudo`, убирайте префикс `sudo` вместе с его параметром `--preserve-env=SSH_CONNECTION`: сама SSH-сессия уже передаёт `SSH_CONNECTION`.

**VPS**:

```bash
sudo apt-get update
sudo apt-get install -y openssh-server openssh-client python3 ufw curl
cd ~/drover-remote/bridge
sudo --preserve-env=SSH_CONNECTION bash ./vps-setup.sh --mac-key ~/mac_bridge_ed25519.pub
```

Скрипт создаст ограниченного пользователя `bridge-mac` и установит политику SSH-перенаправлений: только обратные туннели на loopback-портах VPS **2222 и 8780**, без оболочки и SFTP. Он проверяет фактически действующие SSH-настройки и при ошибке транзакции восстанавливает конфигурацию, ключи и учётные записи. Парольный вход администратора этот скрипт не отключает.

Перед продолжением проверьте **новый** административный SSH-вход с Mac. Если скрипт сообщает о конфликте SSH-правил, устраните указанную причину, не обходите проверку. Из настоящей SSH-сессии выполните (`SSH_CONNECTION` должен сохраниться через sudo):

```bash
sudo --preserve-env=SSH_CONNECTION bash ./vps-setup.sh --check
```

При запуске из консоли провайдера вместо SSH задайте реальный контекст клиента через `--context HOST,CLIENT_IP,VPS_IP,SSH_PORT`; вымышленные адреса не проверяют ваше соединение.

### HTTPS через Caddy

**VPS**, подставьте публичный IPv4 сервера:

```bash
sudo bash ./vps-web.sh --ip YOUR_PUBLIC_IPV4
```

Скрипт установит Caddy из официального репозитория Debian/Ubuntu, если его ещё нет, напечатает HTTPS-адрес, проверит конфигурацию, сохранит прежний Caddyfile и запустит/перезагрузит Caddy. Прокси ведёт на `127.0.0.1:8780`, поддерживает WebSocket и ограничивает тело запроса 20 МиБ. [Caddy автоматически обслуживает HTTPS-сертификаты](https://caddyserver.com/docs/automatic-https). DNS должен указывать на VPS, а **80/TCP и 443/TCP** — быть доступны снаружи, в том числе в фаерволе провайдера.

**502 Bad Gateway** на этом этапе ожидаема: туннель с Mac и веб-сервер Drover ещё не запущены. Необязательный параметр `--basic-auth USERNAME` добавляет отдельный запрос пароля; основной сценарий использует passkey Drover без этого слоя. Basic auth требует дополнительной проверки с установленным веб-приложением и push-уведомлениями.

Для своего домена направьте DNS A-запись на VPS, замените имя сайта sslip.io в `/etc/caddy/Caddyfile` своим доменом, затем выполните `sudo caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile` и `sudo systemctl reload caddy`. Укажите тот же HTTPS-origin в Drover. Повторный запуск `vps-web.sh` снова создаст конфигурацию sslip.io.

### Фаервол с автоматическим откатом

Для нового выделенного VPS, **VPS**:

```bash
sudo --preserve-env=SSH_CONNECTION bash ./vps-firewall.sh --reset
```

`--reset` заменяет существующие правила UFW. Если другие службы используют текущие правила, уберите этот параметр и проверьте `sudo ufw status verbose`. Скрипт сохраняет реальные SSH-порты, разрешает 80/443, запрещает остальные входящие соединения и **до изменения правил** запускает таймер отката на пять минут. В `/etc/default/ufw` должно быть `IPV6=yes`, иначе скрипт откажется работать.

В течение пяти минут откройте **новую SSH-сессию** с Mac. В ней выполните именно команду подтверждения, напечатанную скриптом, например:

```bash
cd ~/drover-remote/bridge
sudo --preserve-env=SSH_CONNECTION bash ./vps-firewall.sh --confirm TOKEN_PRINTED_BY_SCRIPT
```

Токен создаётся для вашего изменения фаервола; чужой токен не подходит. Подтверждение из старой сессии отклоняется. Без подтверждения автоматически вернутся прежние правила и прежнее включённое/выключенное состояние UFW. Не открывайте публично 8780, 7780 и 2222–2224. Фаервол провайдера и опубликованные порты Docker проверяются отдельно.

## 3. Запустите туннель с Mac

**Mac**, в `~/drover-remote` с переменными из шага 1:

```bash
VPS_USER=bridge-mac bash ./install.sh bridge
bash ./install.sh status
```

Установщик получит SSH-ключ VPS и попросит сверить отпечаток. Доверенный отпечаток получите в консоли VPS или уже проверенной административной сессии:

```bash
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

Соглашайтесь только при совпадении. Установщик закрепит ключ в `~/.ssh/mac_bridge_known_hosts`, создаст `~/Library/LaunchAgents/dev.drover.bridge.plist` и загрузит агент для текущего пользователя. launchd перезапускает туннель после завершения процесса. Лог: `~/Library/Logs/dev.drover.bridge.log`.

LaunchAgent работает после входа пользователя, не до него. После перезагрузки с FileVault нужно разблокировать диск и войти в систему; затем снова запустить Drover. При желании добавьте Drover в объекты входа macOS.

**«Удалённый вход» (Remote Login) на Mac необязателен.** Для сайта нужен только веб-порт Drover; дополнительный SSH-туннель может существовать при закрытом порте 22 на Mac. Необязательный SSH-доступ к Mac описан в [remote/README.md](../remote/README.md).

## 4. Включите веб-сервер Drover

На **Mac** откройте Drover → Настройки → **Удалённый доступ**:

1. Укажите **Порт** `7780`.
2. Укажите **Публичный HTTPS-адрес** из вывода `vps-web.sh`, например `https://A-B-C-D.sslip.io`. Нужен только origin: без `/pair`, параметров запроса и фрагмента. Используйте имя хоста, а не голый IP.
3. Включите **Работает через прокси (Caddy на VPS)**.
4. Нажмите **Сохранить**, затем **Включить удалённый доступ**. Проверьте статус, что удалённый доступ работает.

Для этого гайда оставьте 7780. Если нужен другой порт, измените также целевой порт Mac в `bridge/dev.drover.bridge.plist.template` (`127.0.0.1:8780:127.0.0.1:7780`) и повторите `install.sh bridge`. Порт VPS 8780 должен совпадать с Caddy и политикой VPS.

По умолчанию [Caddy обрабатывает forwarded-заголовки](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy#headers), отбрасывая недоверенные входящие значения. Настройка прокси в Drover позволяет принимать один IP клиента из локального туннеля, чтобы лимиты запросов разделялись между посетителями. При добавлении ещё одного прокси сохраняйте публичные Host/Origin; последний прокси должен **заменять** `X-Forwarded-For` одним проверенным IP клиента, а не дописывать данные, присланные браузером.

## 5. Привяжите iPhone и входите через Face ID

1. В настройках Drover на Mac нажмите **Привязать телефон**. Сканируйте QR камерой iPhone и откройте ссылку в **Safari**.
2. При желании задайте имя устройства, затем нажмите **Создать ключ доступа и подключиться**. Подтвердите создание ключа через Face ID, Touch ID или разблокировку устройства. Если passkey недоступен, проверьте поддержку ключей доступа и наличие блокировки экрана.
3. Ссылка действует **10 минут** и используется один раз после успешной привязки. Для каждой регистрации создавайте новую; новый QR заменяет предыдущую ожидающую ссылку.
4. Позже открывайте тот же HTTPS-адрес и выбирайте **Войти с ключом доступа**. Постоянного пароля сайта Drover не выдаёт.

QR и ссылка привязки — секрет: получивший действующую ссылку может зарегистрировать доступ. Не публикуйте её скриншоты.

### «На экран Домой» и уведомления

В Safari выберите **Поделиться → На экран «Домой»** (если предлагается, включите **Открывать как веб-приложение**). Запустите Drover с нового значка. Если приложение попросит вход, используйте passkey по тому же адресу.

В веб-приложении откройте **Настройки → Уведомления**, включите **Уведомления на телефоне** (в некоторых вариантах интерфейса — кнопка включения уведомлений) и подтвердите разрешение iOS. Выберите события завершения работы и ожидания ввода агента. На iPhone push требует установленного веб-приложения с экрана «Домой» и iOS 16.4+, как описано в [документации WebKit](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/). При отсутствии оповещений проверьте также Настройки iOS → Уведомления и режимы фокусирования. Mac, Drover и туннель должны быть в сети, чтобы отправлять события.

### Вход с самого Mac

Открывайте в браузере Mac **тот же публичный HTTPS-адрес**. Используйте синхронизированный passkey, если он доступен, либо создайте новую ссылку привязки в десктопном Drover и откройте/скопируйте её в этот браузер. Можно воспользоваться предложенным браузером входом с passkey телефона.

Если задан публичный адрес, проходите аутентификацию там: `http://localhost:7780` полезен для проверки локального сервера, но создание и проверка passkey относятся к настроенному публичному origin. Переход между localhost, IP, sslip.io и своим доменом может вызвать ошибку passkey.

## 6. Не давайте Mac засыпать

Держите Mac на зарядке и в стабильной сети. В Системных настройках macOS → Аккумулятор → Параметры включите запрет автоматического сна при питании от адаптера и выключенном дисплее, если такая настройка есть; название зависит от версии macOS. Экран может погаснуть, но компьютер должен бодрствовать. Для временной работы с открытой крышкой:

```bash
caffeinate -i -s
```

Оставьте процесс в Терминале; Ctrl+C завершает его. Работа с закрытой крышкой этим не гарантируется.

Для необязательной работы **с закрытой крышкой на зарядке** папка `lid/` содержит помощник с двумя root LaunchDaemon:

```bash
cd ~/drover-remote/lid
sudo bash ./install.sh
launchctl print system/dev.drover.lid-awake
launchctl print system/dev.drover.lid-awake-guard
tail -n 20 /Library/Logs/lid-awake.log
```

Он запрещает сон на AC, возвращает его на батарее/при неизвестном питании и запрашивает сон на батарее с закрытой крышкой. Второй демон страхует от оставшегося запрета сна на батарее. Используется `pmset disablesleep`: **на своей модели Mac и версии macOS** проверьте закрытую крышку и отключение зарядки, находясь рядом с устройством. [Штатный режим Apple с закрытой крышкой](https://support.apple.com/en-us/102501) предполагает внешний дисплей; помощник выходит за рамки этого сценария.

Mac должен стоять на твёрдой проветриваемой поверхности. Перед рюкзаком отключите зарядку и убедитесь, что он действительно уснул. Удаление помощника с возвратом сна:

```bash
sudo bash ./uninstall.sh
```

Подробности и DRY_RUN: [README lid/](../remote/lid/README.ru.md). FileVault остаётся включённым.

## 7. Необязательные Linux- и Windows-машины для агентов

Эти скрипты дают агентам SSH-доступ к другим машинам через тот же VPS. Они **не добавляют поддержку удалённых herdr-машин внутри Drover**: агенты на Mac работают там через `ssh homeserver` / `ssh pc`. Удалённая учётная запись `agent` получает **sudo без пароля на Linux / права администратора на Windows**.

Скопируйте `~/.ssh/agents_ed25519.pub` на каждую целевую машину; приватный ключ остаётся на Mac. Каталоги скриптов копируйте из `remote/`, как описано ниже. Сверяйте отпечаток VPS с доверенным значением.

**Linux (systemd)**: на целевой машине сохраните соседние каталоги `bridge/` и `machine-home/`. Выполните там:

```bash
sudo bash ./machine-home/install.sh --vps-host YOUR_PUBLIC_IPV4 --agent-key ./agents_ed25519.pub --keep-password-login
```

Появятся `agent` и переподключающаяся служба `drover-tunnel` к loopback-порту VPS **2224**. Сохраните напечатанный публичный ключ туннеля в `home_tunnel.pub` на VPS, затем в `~/drover-remote/bridge` выполните:

```bash
sudo --preserve-env=SSH_CONNECTION bash ./vps-setup.sh --home-key ~/home_tunnel.pub
```

Проверьте **новые входы по ключу и как администратор, и как `agent`**. Затем повторите Linux-установщик без `--keep-password-login`, добавив `--key-login-confirmed`. Это отключит SSH-пароли для всех пользователей; у администратора уже должен работать ключ. Статус: `systemctl status drover-tunnel`, лог: `journalctl -u drover-tunnel`.

**Windows 10/11**: скопируйте `machine-pc/install.ps1` и `agents_ed25519.pub` в одну папку. Откройте **64-разрядный PowerShell от имени администратора**:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\install.ps1 -VpsHost 'YOUR_PUBLIC_IPV4' -AgentKeyFile .\agents_ed25519.pub -KeepPasswordLogin -KeepLanSsh
```

Установятся OpenSSH, локальный администратор `agent` и задача `DroverTunnel` от SYSTEM к loopback-порту VPS **2223**. Сохраните её напечатанный публичный ключ в `pc_tunnel.pub` на VPS и выполните там:

```bash
sudo --preserve-env=SSH_CONNECTION bash ./vps-setup.sh --pc-key ~/pc_tunnel.pub
```

После успешного **нового входа по ключу как `agent`** повторите команду Windows с `-KeyLoginConfirmed` вместо `-KeepPasswordLogin -KeepLanSsh`: это отключит SSH-пароли и стандартное правило входящего LAN SSH. Проверка: `Get-Service sshd`, `Get-ScheduledTask DroverTunnel`, лог `C:\ProgramData\drover-tunnel\tunnel.log`. Оболочка SSH по умолчанию — PowerShell, не bash.

**Mac → VPS → машины**: скопируйте `agents_ed25519.pub` на VPS и зарегистрируйте как jump-ключ:

```bash
# VPS, в ~/drover-remote/bridge
sudo --preserve-env=SSH_CONNECTION bash ./vps-setup.sh --jump-mac-key ~/agents_ed25519.pub
# Mac, в ~/drover-remote, с заданными VPS_HOST/VPS_PORT
bash ./install.sh ssh-config
```

Готовый SSH-шаблон использует **`agents_ed25519` и для VPS jump, и для входа на целевую машину**. `install.sh keys` создаёт также `mac_jump_ed25519`; отдельный ключ не используется шаблоном, пока вы сами не измените его `IdentityFile` и не зарегистрируете соответствующий публичный ключ на VPS.

Добавьте **Include-строку, напечатанную установщиком**, в самый верх `~/.ssh/config`. Первые соединения выполните вручную: `ssh -o StrictHostKeyChecking=ask pc` / `ssh -o StrictHostKeyChecking=ask homeserver`. Сверьте отпечатки целевых машин с `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub` на Linux или `ssh-keygen -lf C:\ProgramData\ssh\ssh_host_ed25519_key.pub` на Windows. Последующие подключения требуют закреплённых ключей. CLI агентов и нужные инструменты на целевых машинах устанавливайте отдельно; не обходите ошибки host key.

## Безопасность и отзыв доступа

- Доступ к сайту означает **полный доступ к агентам и их терминалам**, включая файлы, секреты и разрешения, которыми могут пользоваться агенты. Это не панель только для просмотра. Необязательные машинные учётки расширяют этот доступ на другие компьютеры.
- На десктопном Mac: Настройки → Удалённый доступ → **Привязанные устройства → Отозвать**. Отзыв убирает доступ регистрации и её push-подписки. Выход из браузера сам по себе не отзывает passkey. Синхронизированный passkey может использоваться на нескольких физических устройствах; отзыв его регистрации Drover действует везде, где она используется.
- Выключите **Включить удалённый доступ**, чтобы остановить веб-интерфейс. Обновляйте Drover, macOS, Caddy и пакеты VPS. HTTPS завершается на VPS: администратор VPS может видеть трафик, поэтому защитите сервер.
- Не публикуйте HTTP-порт Drover и обратные SSH-порты. Сохраните проверенные ограничения перенаправлений и сверку host key. Сгенерированный Caddyfile не ведёт access log и удаляет URI/Referer из runtime-логов, чтобы не хранить секреты привязки; сохраняйте эту политику при правках.
- **Пароль root от провайдера — начальный доступ**, а не ключ туннеля. На Mac создайте отдельный административный SSH-ключ (например `ssh-keygen -t ed25519 -f ~/.ssh/drover_vps_admin_ed25519`), добавьте его `.pub`-строку в `~/.ssh/authorized_keys` нужного администратора VPS и проверьте новый вход: `ssh -i ~/.ssh/drover_vps_admin_ed25519 -p "$VPS_PORT" "$VPS_ADMIN@$VPS_HOST"`. Только после этого отключайте парольную аутентификацию, а при наличии отдельного sudo-пользователя — и вход root. Проверьте `sudo sshd -t`, действующие настройки `sudo sshd -T` и перезагрузите SSH, сохраняя открытую сессию и доступ к консоли провайдера. Скрипт VPS ограничивает bridge/jump-пользователей; администратора автоматически не защищает.

Для удаления туннеля Mac выполните `bash ./install.sh uninstall` в `~/drover-remote`: приватные ключи сохранятся, LaunchAgent и закреплённый ключ VPS удалятся; необязательный sshd drop-in Mac удалится через sudo. Помощник `lid/` удаляется отдельно. Это не удаляет Caddy/UFW на VPS и службы других машин. Выключите удалённый доступ также в Drover.

## Устранение проблем

| Симптом | Что проверить |
| --- | --- |
| **502 Bad Gateway** | Drover запущен, удалённый доступ включён на 7780. Mac: `bash ./install.sh status`, `tail -n 30 ~/Library/Logs/dev.drover.bridge.log`, `curl -I http://localhost:7780/login`. VPS: в `sudo ss -ltnp` должен быть `127.0.0.1:8780`; `curl -I -H 'Host: YOUR_HOSTNAME.sslip.io' http://127.0.0.1:8780/login`; `sudo journalctl -u caddy -n 50`. Локальный 200/redirect проверяет ответ HTTP-сервера, не вход через passkey. |
| **Ошибка passkey / неправильный адрес** | URL браузера, имя сайта Caddy и публичный HTTPS-адрес Drover должны совпадать, включая нестандартный HTTPS-порт. При настроенном публичном origin не входите через IP или localhost. После смены имени сохраните настройки и заново привяжите устройство по новому адресу. |
| **Ссылка привязки истекла/использована** | Создайте новый QR на Mac и используйте в течение 10 минут. Новый QR отменяет предыдущий ожидающий код. |
| **Ошибка сертификата / сайт недоступен** | Проверьте DNS: `dig +short YOUR_HOSTNAME.sslip.io`, входящие 80/443 в UFW и фаерволе провайдера, логи Caddy. DNS/VPN-фильтр может блокировать домены с IP внутри: используйте разрешённый резолвер или собственный домен. |
| **Туннель постоянно перезапускается** | У `bridge-mac` должен быть соответствующий публичный ключ; проверьте `vps-setup.sh --check`. `remote port forwarding failed` может означать, что 8780/2222 ещё заняты старой сессией: подождите около 90 секунд, пока keepalive закроет мёртвую сессию. Не убивайте посторонние процессы sshd. |
| **Host key verification failed** | Сверьте новый отпечаток через консоль провайдера/целевую машину. Только затем обновите нужную запись known_hosts. При смене VPS или его адреса закреплённый файл сохраняется: обновите его осознанно до переустановки. Не используйте `StrictHostKeyChecking=no`. |
| **Без VPN работает, с Happ или похожим VPN — нет** | На Mac и iPhone сравните с отключённым VPN, включая **kill switch / блокировку соединений без VPN**. Некоторые клиенты сохраняют блокировку даже после отключения туннеля. Проверьте маршрутизацию, DNS и исключения для IP/имени VPS. Это диагностика; затем верните нужную конфигурацию VPN. |
| **Конфликт VPN на iPhone** | Рассчитывайте на один активный персональный VPN-туннель. Happ и Tailscale могут отключать/заменять друг друга; выберите один путь подключения, не рассчитывая на одновременную работу двух персональных VPN. |
| **SSH зависает через VPN** | Mac: `nc -vz "$VPS_HOST" "$VPS_PORT"`. VPN/сеть могут блокировать **22/TCP**, хотя HTTPS работает. Настройте маршрут VPN или другой реальный SSH-порт VPS; задайте `VPS_PORT` и переустановите мост Mac. На других машинах используйте `--vps-port` / `-VpsPort`. До изменения доступа разрешите новый порт в фаерволе провайдера. |
| **Нет уведомлений** | Откройте приложение с экрана «Домой», войдите, включите уведомления в приложении и разрешите их в iOS. Проверьте фокусирование и сеть/VPN; Mac должен быть онлайн. |
| **Недоступен после перезагрузки или закрытия крышки** | Разблокируйте FileVault, войдите и запустите Drover; проверьте LaunchAgent и отсутствие сна. Помощник крышки сначала проверьте локально. |

Если 7780 занят, остановите конфликтующую службу или согласованно измените порт Drover и целевой порт туннеля Mac. Не меняйте только поле в Drover.

## Альтернативы без VPS — с Drover не проверялось

- **[Tailscale Serve](https://tailscale.com/kb/1242/tailscale-serve)** может открыть локальный порт Drover по HTTPS внутри вашей tailnet. Нужен Tailscale на Mac и телефоне и включённое HTTPS-имя. Укажите этот origin в Drover и проверьте привязку, заголовки прокси и уведомления. Учитывайте конфликт VPN на iPhone выше.
- **[Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/)** может направить стабильное HTTPS-имя на локальный порт через `cloudflared` на Mac. Для постоянного публичного имени обычно нужен домен под управлением Cloudflare. Задайте соответствующий origin в Drover и проверьте Host/Origin, WebSocket и передачу IP клиента. Временные/случайные имена не подходят для долговременных passkey.

Это возможные альтернативы, **не проверенные инструкции установки**. В обоих случаях Mac и Drover всё равно должны оставаться запущенными.
